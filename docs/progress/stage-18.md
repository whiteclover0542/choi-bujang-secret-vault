# 18단계 — 근거가 있는 AI 사건 설명

## 19단계 시작 시 확인

- 사용자가 18단계 공식 통과를 전달했습니다. 포털 직접 조회는 하지 않았으며 실제 사건 설명의 로컬 검증과 구분합니다.
- 저장한 커밋은 `ac7c99c6a04039311021283535a0982790338263`입니다. 실제 판정 대상 커밋은 포털과 별도로 대조하지 않았습니다. 아래 미확인 기록은 당시 작업 이력입니다.

## 목표와 범위

- 17단계 공식 통과는 사용자 전달로 확인했습니다. 포털 직접 조회나 실제 사건 설명 호출 성공을 뜻하지 않습니다.
- `on-client/student/extension.mjs`의 `renderExplanation({ event, explanation, checkedAt })`만 확장합니다. 앞 단계 함수와 제공 서버·UI·인증 설정 및 기존 0.2.21 업데이트 변경을 보존합니다.
- 제공 UI는 설명의 근거 전체 인용, 없는 ID·중복·지원하지 않는 조치·비밀 표기·실행 여부를 검사한 뒤 학생 함수에 전달합니다.
- 설명 data는 `{ summary, evidenceIds, proposals:[{action,evidenceIds,reason}], requiresHumanConfirmation:true, executed:false }`입니다. event는 15단계 사건 또는 null입니다.

## 구현 순서

1. 오류를 event 없음보다 먼저 처리합니다. 자료 없음·요청 중·대기·성공·실패를 구분합니다.
2. 성공 자료의 근거 ID를 현재 사건과 대조한 뒤 성공 속성을 붙입니다. 이미 실행됐다는 설명과 근거 불일치는 거절합니다.
3. 참고용 요약, 근거 ID·문장, 규칙 ID·문장, 접속·세션·기기의 unknown을 표시합니다.
4. 제안의 조치·이유·근거와 사람 확인 필요·미실행을 표시합니다. 지원 조치가 없는 경우 제안이 없는 이유를 설명합니다. 실행 버튼을 만들지 않습니다.
5. 매 호출 새 DOM으로 이전 설명과 성공 속성을 남기지 않습니다. 비동기 취소·다른 사건 선택 시 늦은 응답 처리는 제공 UI가 담당하며 수정하지 않습니다.

## 검증 계획

- 문법 검사: `npm --prefix on-client run check`.
- 모의 DOM: 두 사건의 근거·규칙 분리, unknown 세 항목, 제안 없음·제안 미실행, event 없는 오류, 근거 부족·불일치, executed:true 거절, 새 입력의 성공 속성 제거와 앞 단계 보존.
- 실제 화면·실제 AI 호출·계정 및 기존 엔진 연결·늦은 응답 경합·공식 판정은 별도 확인합니다. 모의 검사를 공식 통과로 기록하지 않습니다.
- 필수 항목: student-source-changed, evidence_binding, unknown_evidence, insufficient_evidence, wrong_event_rejected, proposal_not_executed, non_ai_regression, explanation_refresh.

## 직접 확인 첫 단계

- 앱이 실행 중이면 새 서버를 중복 실행하지 말고 Ctrl+F5 후 보안 기록으로 이동합니다.
- 정상 예상: 선택한 기록이 없으면 「보안 기록에서 기록을 먼저 고르세요」. 오류 입력이 있다면 기록 선택 안내보다 안전한 실패 원인이 먼저 나옵니다.
- 거절되어야 할 결과: 근거가 없거나 다른 사건의 근거로 성공 표시, unknown을 정상으로 표시, AI 제안 자동 실행.
- 실제 기록 조회가 막히면 실제 설명 검증은 미확인으로 남기며 유료 요청을 반복하지 않습니다.

## 구현 및 실행 결과

- `renderExplanation`만 확장했습니다. 오류 우선, 기록 선택 안내, 요청 중, 참고용 요약·현재 근거·규칙·unknown 표시, 제안의 근거와 이유·미실행, 지원 조치 없는 정상 상태를 구현했습니다.
- 없는 근거·빠진 인용·빈 근거, 실행됐다는 응답, 현재 사건과 맞지 않는 제안은 성공 속성 없이 거절합니다. 제공 UI에서 정제된 오류 코드·메시지를 사용하며 알 수 없는 원문 오류는 표시하지 않습니다.
- 저장소 밖 임시 모의 DOM 검사 12건을 실행했습니다. 구현 전 10건 실패·2건 성공으로 미구현 요구를 확인했고, 구현 뒤 12건 모두 통과했습니다. 실제 네트워크·AI 요청은 없습니다.
- `npm --prefix on-client run check`와 학생 코드의 `git diff --check`를 실행해 오류가 없었습니다. 모의 검사는 브라우저·실제 모델 호출·공식 판정 결과가 아닙니다.
- 다른 사건·idle·loading·실패 입력마다 새 요소를 반환합니다. 실제 비동기 늦은 응답 거절은 제공 UI의 generation 검사에서 처리함을 코드로 읽었으며 실제 화면에서는 미확인입니다.
- 실제 서버의 기록 조회는 직전 사용자 화면에서 연결 확인 불가였습니다. 실제 사건 2건 설명, 실제 타 사건 전환 경합, 실제 업무 앱·기록 회귀, 공식 판정·커밋·제출은 미확인/미실행입니다.
