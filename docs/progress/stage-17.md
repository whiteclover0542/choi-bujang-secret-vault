### 입력과 표시 계약

`renderAiConnection({ status, mode, data?, error?, checkedAt, explanationAccepted })`

- data: `{ transportChecked:true, audienceAuthorization:'test'|'verified', modelCount, help }`.
- explanationAccepted는 제공 계약상 false입니다. 모델 목록 응답을 사건 설명 성공으로 표현하지 않습니다.

| 상황 | 표시 |
| --- | --- |
| idle | AI 연결 점검 전. 이전 점검 결과 제외 |
| loading | AI 연결 점검 중. 이전 결과를 현재처럼 유지하지 않음 |
| ok + test | 시험 연결 점검(test), modelCount와 checkedAt |
| ok + verified | 앱 권한 확인 후 점검(verified), modelCount와 checkedAt |
| 모든 ok | 사건 설명은 아직 실행하지 않았습니다 |
| error | 안전한 code·message, 원인별 안내. 원문 오류·열쇠 제외 |

- 권한 준비 중·확인 불가는 담당자에게 계정·앱 권한 확인을 요청하도록 안내합니다. 학생 잘못이나 연결 완료로 표시하지 않습니다.
- 인증·접근 제한, 반 사용량·이용 한도, 이용 시간, 요청 제한·시간 초과·네트워크, 취소, 모델 없음 등을 공식 오류 코드와 대조해 구분합니다. 코드명을 추측해 운영 계약을 바꾸지 않습니다.
- 다시 점검한 성공이나 계정 변경의 idle 입력에서 이전 오류·성공 결과를 교체합니다. 취소는 취소로 표시하고 이전 결과를 현재 것으로 되살리지 않습니다. 자동 재점검은 추가하지 않습니다.

`renderExplanation({ event, explanation, checkedAt })`

- explanation.status가 ok면 바깥 반환 요소에 `data-student-explanation-event`를 event.id로 지정하고 사건 ID와 explanation.data.summary를 textContent로 표시합니다.
- 실패면 안전한 code·message와 「기록은 그대로입니다」를 표시합니다. 실패 요소에는 위 성공 속성을 붙이지 않습니다.
- 18단계에서 설명 기능을 확장합니다. 이번 단계에서 임의 조치·자동 실행·대체 모델을 추가하지 않습니다.
- DOM은 createElement와 textContent로 구성하고 API 값·함수명·필수 버튼 이름과 앞 단계 코드를 유지합니다.
