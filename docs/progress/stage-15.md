## 완료한 일

- 현재 `renderEvents`는 대기 문자열을 반환합니다. 제공 `public/app.js`의 `studentData`는 events 스냅샷을 전달하며, events 갱신 시 `renderStudent('events')`를 호출합니다. 학생 함수의 반환 DOM은 제공 UI가 교체합니다. 코드로만 확인했고 제공 코드는 수정하지 않았습니다.
- 공식 상대 경로 앞에 실제 프로젝트에서는 `on-client/`가 붙습니다. 계약을 바꿔 새 API나 입력을 만들 필요는 없습니다.

### 입력 계약

`renderEvents({ status, mode, data?, error? })`

- data는 `{ id, kind, at, appId, summary, evidence:[{id,text}], rules:[{id,text}], state:{access,session,device}, supportedActions }` 배열입니다.
- kind: access=접속 기록, xdr=XDR 경보. 원래 코드도 표시합니다.
- state.access: allowed=접근 허용, denied=접근 거부, unknown=확인 불가.
- state.session: active=활성, expired=만료, revoked=철회됨, unknown=확인 불가.
- state.device: compliant=보안 기준 충족, noncompliant=보안 기준 미충족, unknown=확인 불가.
- 세 상태는 따로 표시하고 한국어와 원래 코드를 병기합니다. unknown을 정상으로 바꾸지 않습니다.

### 목록·필터·상세 계약

- 원본 배열을 복사한 뒤 at 최신순 정렬합니다. 사건 ID·시각·종류·앱 ID·요약을 실제 글자로 표시하고 각 행에 `data-student-event-id`를 사건 ID로 지정합니다. 앱 ID가 없으면 앱 확인 불가를 표시합니다.
- 세 select의 접근 가능한 이름은 「기록 종류」「업무 앱」「접속 상태」입니다. 전체 값은 all이며 나머지는 받은 kind·appId·state.access 원래 값입니다. 필터는 받은 배열에서만 적용하고 서버 재요청을 만들지 않습니다. 필터 결과 건수와 실제 행이 일치해야 합니다.
- 각 행의 버튼 이름은 `<event.id> 상세`입니다. 상세 영역에는 `data-student-event-detail`을 사건 ID로 지정하고 사건 ID·앱 ID, evidence의 id·text, rules의 id·text와 세 상태를 구분해 표시합니다.
- 새 자료가 전달되면 이전 목록과 상세 선택을 초기화합니다. 필요하면 같은 파일 안에 필터 상태를 둘 수 있습니다.
- createElement와 textContent로 DOM 요소를 반환합니다. `<b>` 같은 입력도 글자 그대로 표시하며 innerHTML은 쓰지 않습니다. label과 기본 버튼으로 키보드 조작을 지원합니다.

| 입력 상태 | 표시 |
| --- | --- |
| loading | 기록을 불러오는 중임을 표시, 이전 목록·상세 제외 |
| ok + 기록 있음 | 정렬된 목록과 필터·상세 |
| ok + 빈 배열 | 표시할 기록이 없습니다 |
| error | 기록을 불러오지 못했습니다: 서버 message. 이전 목록·상세 제외 |
| CONTRACT_MISMATCH 오류 | 확인 불가 안내, 이전 목록·상세 제외 |
| mode demo / disconnected / unknown | 예제 자료 / 연결 없음 / 확인 불가를 전달된 상태와 함께 구분 |

### 관측 범위와 보존 사항

- 본인 SDP 감사 기록 중 현재 등록 정보와 맞는 최근 40건까지입니다. 전체 직원 로그나 실시간 전체 위협 탐지를 의미하지 않습니다.
- 전체·생략 건수와 확인 시각은 제공 화면의 정보입니다. 학생 함수에 전달되지 않은 수치를 추측하지 않습니다.
- XDR은 이미 저장된 경보입니다. 화면에서 새 탐지를 실행하지 않습니다. 과거 기록의 appId 누락과 세션·기기 unknown을 그대로 구분합니다.
- 실제 조치 버튼은 만들지 않습니다. supportedActions가 비어 있을 때도 추가하지 않으며 연결되지 않은 조치 안내는 16단계 범위입니다.
- 제공 서버·public/app.js·판정 코드·인증 설정은 수정하지 않습니다. 비밀값·개인정보를 문서나 로그에 기록하지 않습니다.
