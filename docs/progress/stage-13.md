### 공식 입력 계약과 구현 범위

- 수정 대상은 `student/extension.mjs`의 `renderIdentity`만입니다. `createStudentView`는 구조 확인 대상으로 읽고, 다른 함수의 기본 문구와 기존 기능은 보존합니다.
- 입력은 `renderIdentity({ me, devices, sessions })`이며 각각 `{ status, mode, data?, error? }`입니다.
- `me.data`는 `{ user: { id, label }, device: { id, label, status }, session: { id, status } }`입니다.
- `devices.data`는 `[{ id, label, status }]`, `sessions.data`는 `[{ id, status }]`입니다. 사용자 label·id, 기기 label·id·status, 세션 id·status를 입력에서 읽습니다.
- DOM은 `document.createElement`와 `textContent`로 작성하고 요소 하나를 반환합니다. `innerHTML`은 사용하지 않습니다. API 상태값·함수명·`data-*` 속성·필수 버튼 이름을 유지합니다.
- 색상뿐 아니라 텍스트로 상태를 구분합니다. 조작 요소가 필요하면 키보드로 조작할 수 있는 label과 버튼을 사용합니다.

| 구분 | 입력값 | 표시 |
| --- | --- | --- |
| 요청 상태 | loading | 불러오는 중 |
| 요청 상태 | ok | 해당 입력의 사용자·기기·세션 값 |
| 요청 상태 | error | 연결 실패와 `error.message`를 텍스트로 표시, 이전 사용자 값 제거 |
| 기기 상태 | compliant / noncompliant / unknown | 보안 기준 충족 / 보안 기준 미충족 / 확인 불가 |
| 세션 상태 | active / expired / revoked / unknown | 활성 / 만료 / 철회됨 / 확인 불가 |
| 자료 모드 | demo / disconnected / unknown | 예제 자료 / 연결 없음 / 확인 불가 |

- 모드 안내는 loading·error 상태에서도 함께 표시합니다. noncompliant·expired·revoked를 정상 상태처럼 표시하지 않습니다.
- 새 데이터가 전달되면 이전 사용자·기기·세션 DOM을 교체해야 합니다. 실제 교체 방식은 제공 UI 원문을 확보한 뒤 확인합니다.
- 기기 보안 상태 표시는 악성코드 검사나 치료 기능이 아닙니다.
