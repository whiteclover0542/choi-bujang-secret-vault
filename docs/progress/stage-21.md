# 21단계 — 다른 사람이 이해할 수 있는 문서

## 목표와 현재 상태

- 20단계 공식 통과는 사용자 전달로 확인했습니다. 이 문서는 첨부된 21단계의 다음 작업 안내이며 21단계 구현·공식 통과 기록은 아닙니다.
- 목표: 다른 사람이 실제 작업 위치와 실행 명령을 확인하며 프로젝트를 실행할 수 있도록 학생 실행 설명서와 글로 쓴 구성도를 작성합니다.
- 다음 작성 대상: 루트 README의 학생 부분과 새 `docs/STUDENT_RUNBOOK.md`(예시 이름). 제공 문서를 덮어쓰거나 UI·실행 코드를 불필요하게 변경하지 않습니다.
- 기존 학생 코드·기능·Git 기록·미커밋 문서 변경을 보존합니다. 제공 서버·public/app.js·판정·인증 설정은 수정하지 않습니다.

## 문서 작성 순서

1. 현재 package.json·설정·잠금 파일·실행 도구·모듈과 기존 학생 문서를 읽고 일치 여부를 확인합니다. 파일이 없거나 계약이 다르면 그 차이를 적고 새 구조를 추측하지 않습니다.
2. README 학생 부분에 목적·기능·구성·지원 환경·확인한 버전과 실행 설명서 링크를 정리합니다.
3. 학생 실행 설명서에 필요한 프로그램, 실제 확인한 버전, 폴더 구조, PowerShell 작업 위치, 명령, 브라우저 주소, 정상 시작 신호, 종료·재실행 순서를 적습니다.
4. 브라우저 → 로컬 앱 서버 → 접근 제어·XDR 시스템 / AI 게이트웨이의 관계를 Mermaid·ASCII·표 등 텍스트로 표현합니다. 실제 모듈·데이터 흐름과 대조하며 공개 가능한 주소·경로만 사용합니다.
5. 구현한 학생 함수·제공 코드 경계·확인한 기능·오류별 확인 및 복구 순서·미지원 환경·미확인 기능을 표로 정리합니다.
6. 새 PowerShell 창에서 기존 작업을 보존하며 실행 절차를 확인합니다. 실제 실행한 것과 코드만 읽은 것, 사용자 화면 확인, 모의 검사를 구분합니다.

## 확인 기준과 한계

- 실제 명령·경로·버튼 이름을 프로젝트와 대조하고, 실행하지 않은 명령이나 연결 성공은 확인했다고 적지 않습니다.
- 정상 예상: 문서의 작업 위치·명령·모듈·오류 안내가 같은 커밋의 코드와 일치합니다.
- 허용하면 안 되는 설명: 모의 결과를 운영 연결·실제 집행 성공으로 기록하거나, 조회 실패를 안전으로 기록하거나, 서버 AI 판정이 새 환경 재현을 수행했다고 설명하는 것.
- 키·토큰·비밀번호·개인 자격 파일과 실제 개인정보를 문서·Git·원문 묶음에 넣지 않습니다. 비밀 입력은 공식 설정 경로에서 사용자가 직접 하며 값을 요구하거나 출력하지 않습니다.
- 21단계 서버 AI는 제출 커밋의 코드·README·학생 문서·설정 설명·재현 기록을 읽어 일치 여부를 판정합니다. 명령 실행이나 새 환경 재현을 인증하는 것이 아닙니다.

## 커밋·원문 제출 절차

- 학생 문서와 해당 단계 코드는 같은 커밋에 저장합니다. 다른 미커밋·스테이징 변경을 먼저 확인하고 보존합니다.
- 첨부 공식 안내에 따르면 21·22단계는 과제 화면에서 저장소 주소와 40자리 커밋을 직접 입력합니다. 현재 워크벤치의 포털 제출 준비는 13~20단계용이며 최종 제출 시 실제 과제 화면 안내와 대조합니다.
- 비공개 저장소는 공개로 바꿀 필요가 없습니다. 해당 단계의 「비공개 저장소 원문 준비 방법」에서 안내하는 도구를 프로젝트 밖에 두고, 출력 JSON도 프로젝트 밖 새 폴더에 만듭니다.
- `student-source-cli.mjs`의 구체적인 명령은 실제 과제 화면을 확인한 뒤 안내합니다. Git 최상위 폴더·도구 경로·출력 경로·40자리 커밋을 확인하며 임의 옵션을 만들지 않습니다.
- 도구는 커밋된 원문만 묶고 학생 코드를 실행하거나 업로드하지 않습니다. 생성된 JSON을 해당 단계 원문 묶음 칸에 선택한 뒤 저장소·커밋·단계를 대조해 사용자가 제출합니다.
- 원문 전달 완료와 AI 통과는 다릅니다. 판정 확인 불가는 불합격·통과로 단정하지 않습니다. 원문 전달만 실패하면 기존 접수를 보존하고 「원문만 다시 보내기」를 사용합니다.

## 이번 문서 정리 결과

- 20단계 통과 기록과 21단계 작업 범위를 정리했습니다. 본문 실행 설명서·구성도는 아직 작성하지 않았습니다.
- 21단계 새 환경 실행·재현·공식 판정은 미확인입니다. 코드·패키지·운영 설정 변경, 커밋·푸시·단계 제출은 하지 않았습니다.
- 다음 작업은 현재 구현·실행 도구를 읽고 학생 실행 설명서와 텍스트 구성도를 작성하는 것입니다.

## 작성 및 대조 결과

- 이후 루트 README에 학생 앱의 목적·기능·지원 환경·버전·설명서 링크를 추가하고 새 `docs/STUDENT_RUNBOOK.md`를 작성했습니다. 제공 문서·실행 코드·UI·설정은 수정하지 않았습니다.
- 실제 실행 위치·명령·주소·정상 시작 신호·종료·재실행·폴더 구조, Mermaid와 텍스트 데이터 흐름, 학생 8개 함수와 제공 모듈 경계, 공개 origin·오류별 복구·검증 한계를 정리했습니다.
- 직접 실행한 버전 확인: Node v24.19.0, npm 11.17.0, Windows PowerShell 5.1.26100.9711. on-client/package.json은 0.2.21이며 외부 의존성과 자체 package-lock.json이 없습니다. 루트 잠금 파일과 구분했습니다.
- 기록된 주요 모듈 경로의 존재를 확인했고 제공 launcher의 명령·정상 신호·버전 제한 및 서버의 실제 API·origin·엔진 선택을 코드와 대조했습니다.
- 기존에 켜져 있던 `http://127.0.0.1:5189/`에 GET 요청해 HTTP 200을 확인했습니다. 기존 서버를 종료하거나 새 서버를 켜지는 않았습니다. 실제 승인·AI·OSV·보안 조치 요청은 하지 않았습니다.
- `npm --prefix on-client run check`를 실행해 문법 검사가 통과했습니다. 문서의 다른 실행 예시·새 PowerShell 최초 실행·종료·재실행·새 PC 재현·공식 판정은 미확인입니다.
- 새로 열린 총공세 가이드 두 파일은 12단계용이므로 그 안의 운영·측정 명령을 21단계 작업으로 실행하지 않았습니다.
- 다음 직접 확인은 새 PowerShell에서 실제 on-client 폴더로 이동한 뒤 기존 서버 창이 실행 중인지 확인하는 것입니다. 실행 중이면 중복 실행하지 않습니다. 사용자가 정상 종료한 경우에만 문서의 실행 명령으로 재시작합니다.
