## 실행 준비

일반 PowerShell을 사용합니다. 자신의 프로젝트 안 `on-client` 폴더를 탐색기로 열고 주소 표시줄에 `powershell`을 입력합니다. 다음 명령이 True인지 먼저 확인합니다.

```powershell
Test-Path .\tools\start-alekov.ps1
```

False면 올바른 `on-client` 폴더를 다시 열고, True이며 서버가 꺼져 있을 때만 실행합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
```

서버 창에 표시된 주소(기본 `http://127.0.0.1:5189/`)를 엽니다. 서버가 이미 켜져 있으면 중복 실행하지 않고 Ctrl+F5로 화면을 갱신합니다. 서버 창은 열어 둡니다. 종료는 해당 창에서 Ctrl+C, 재실행은 같은 명령입니다. 자세한 환경·오류 안내는 [학생 실행 설명서](STUDENT_RUNBOOK.md)를 따릅니다.

키보드는 Tab으로 버튼에 이동해 Enter, 펼침 제목에서 Space를 사용합니다. 재조회 중에는 중복 요청이 차단됩니다. 실제 실패를 만들기 위해 권한·방화벽·보안 설정을 바꾸지 않습니다.

정상 조회에서는 값·단위·시각이 있어야 합니다. 읽지 못한 항목은 「확인 불가」·이유·다음 할 일을 표시해야 하며 0이나 예시 숫자를 정상값으로 대신하면 안 됩니다. 실패·취소 뒤 이전 값이 현재 정상값으로 남아서는 안 됩니다. 이 실패 조건의 실제 OS 재현은 아래와 같이 미확인입니다.

## 실측과 예시의 구분

학생 대시보드는 예시 숫자를 사용하지 않습니다. 조회 전·실패·오래된 값은 확인 불가로 표시하고, 과거 실측은 시각이 붙은 기록으로만 구분합니다. 교육 안내 페이지의 ‘예시 화면·설명용’ 그림은 앱 실측 근거가 아닙니다. 다른 제공 영역에서 demo 표시가 나오면 실제 연결 성공으로 소개하지 않습니다.

CPU는 짧은 구간의 사용률이며 작업 관리자와 측정 시점·집계 범위가 다를 수 있습니다. 메모리·디스크 용량은 GiB(1024³ byte)입니다. 카드의 반올림된 사용률과 원본 비율로 계산한 변화량은 차이가 날 수 있습니다. 메모리 화면의 80.1% → 79.9%와 ‘0.1%p 감소’는 전달된 화면 그대로 기록하며, 반올림 전 원본 값은 그 캡처에서 확인하지 못했습니다.

## 남은 한계·확인 불가

- 운영 SDP 인증·기존 업무 앱·보안 기록 연결, 실제 AI 사건 설명·원천 조치 집행은 이번 마무리의 성공 근거가 없습니다. 과거 AI 연결 점검 verified는 실제 사건 설명·집행 성공과 다릅니다.
- 패키지 조회는 앞선 화면에서 `PROJECT_NOT_CONFIGURED`였습니다. 현재 운영 설정이나 OSV 조회 성공을 새로 확인하지 않았습니다.
- 실제 권한 거절·시간 초과·취소 경합·다른 OS·새 PC 재현은 미확인입니다. 실제 환경의 모든 실패 조건을 통과했다고 말하지 않습니다.
- 기록은 이 탭 메모리에 최근 30회만 남고 새로고침하면 사라집니다. 자동 연속 감시·영구 저장·침해 탐지 기능이 아닙니다.
- 실측은 60초가 지나면 현재 값 확인 불가로 바뀝니다. 직접 다시 조회해야 하며 값 갱신을 위해 보안 설정을 바꾸지 않습니다.
- Windows 기록은 System·Application 최근 24시간, 최대 5,000건의 제공 조회 범위입니다. 부분 집계 여부를 확인해야 하며 0건도 전체 안전의 근거가 아닙니다.
- 화면 폭에 따라 네 카드가 여러 줄로 배치됩니다. 아래 추이·기록과 함께 관제 대시보드 틀을 유지합니다.
- 포장·설치 프로그램·새 배포·최종 제출은 이번 문서 작성에서 수행하지 않습니다.

## 다시 확인하는 순서

1. 위 실행 명령으로 앱을 켜고 표시된 주소를 엽니다.
2. 다시 조회를 두 번 완료해 카드별 시각·단위, 비교 시각, 그래프·기록의 표본을 대조합니다. 다른 시각·PC에서는 숫자가 달라도 됩니다.
3. 상세를 펼쳐 네트워크·방화벽·Windows 기록의 출처·범위와 SDP 별도 표시를 확인합니다.
4. Tab·Enter·Space로 조회와 펼침을 조작합니다. 확인하지 못한 조건은 미확인으로 남깁니다.
5. 문법은 `on-client`에서 `npm run check`로 확인합니다. 제출 번호는 저장소 루트에서 `git rev-parse HEAD`로 확인합니다.

실행 오류가 있으면 첫 오류·실행 명령·현재 폴더만 확인합니다. 비밀값·인증 파일·실제 IP·이벤트 원문은 문서나 제출물에 넣지 않습니다. 기존 프로젝트·제출물·DB를 지우거나 옮길 필요가 없습니다.
