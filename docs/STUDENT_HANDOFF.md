## 옮길 파일과 설치 경계

- 저장소의 추적 파일을 `git clone`으로 받습니다. 실행·구성은 [학생 실행 설명서](STUDENT_RUNBOOK.md)를 따릅니다.
- `on-client`는 외부 npm 의존성과 자체 package-lock.json이 없습니다. 이 재현에서는 npm 설치 없이 제공 Node 코드와 브라우저 파일을 사용했습니다.
- 루트 package.json·package-lock.json(lockfileVersion 3)은 앞 단계 웹 자료실용입니다. 루트 의존성 재설치·Vercel 재배포·Supabase 설정·자료실 기능 재현은 이번 범위에 포함하지 않았습니다.
- 공개 설정 견본과 실행 도구는 코드와 함께 보존합니다. 루트 `aleph.config.json` step 12는 후반 과제 번호와 별개이고 judgeIssuer를 변경하지 않습니다.
- 비밀값, 개인 설정·인증서·키·토큰·쿠키, 실제 메모 본문과 DB 사본은 clone·Git·제출 묶음 대상이 아닙니다. 원래 계정 보관소를 복제본에 복사하지 않습니다.
- 새 위치에서 계정 연결이 필요하면 제공 `start-alekov.ps1`의 자동 개인 보관소 준비와 사용자 승인을 따릅니다. 이번 재현은 `-NoNativeHost`와 `-Demo`만 사용해 이 연결은 실행하지 않았습니다.

## 실제 실행한 절차

기존 폴더에서 Git 상태·원격 URL·브랜치·HEAD를 먼저 확인했습니다. 기존 미커밋 단계 문서를 보존하고 새 폴더에 GitHub 원문을 복제했습니다.

```powershell
git clone --no-checkout https://github.com/whiteclover0542/choi-bujang-secret-vault.git D:\SR\aegis-repro-20261103-stage22
git -C D:\SR\aegis-repro-20261103-stage22 checkout --detach 3d8be7bce0293c543be1a6f99728dbb895bd496a
git -C D:\SR\aegis-repro-20261103-stage22 rev-parse HEAD
npm --prefix D:\SR\aegis-repro-20261103-stage22\on-client run check
```

실제 결과: 지정한 HEAD 일치, 앱 0.2.21 문법 검사 종료 코드 0. 빈 경로에서 clone했고 기존 폴더를 덮어쓰지 않았습니다. 이후 명령은 복제본의 `on-client`에서 실행했습니다. 5192는 기존 사용자 서버의 5189와 구분한 재현 전용 포트입니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -NoNativeHost -Port 5192 -Background
```

정상 시작 문구와 재현 서버 PID 29568을 받았습니다. 별도 headless Edge 세션에서 `http://127.0.0.1:5192/`를 열었습니다. 사용자 브라우저의 로그인·쿠키를 가져오지 않았습니다.

PID와 실행 경로가 복제본의 `src/server.mjs`인지 확인한 후 이 서버만 종료했습니다. 같은 명령으로 PID 30316의 서버가 다시 시작됐고 HTTP GET `/` 결과 200을 확인했습니다. 이것은 실제 프로세스 종료·재실행 관측이며, Ctrl+C 수동 종료 자체를 이번에 시험한 것은 아닙니다.

해당 복제본 서버를 종료한 뒤 예제 모드로 다시 실행했습니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -Demo -Port 5192 -Background
```

PID 28488의 예제 서버에서 「업무 앱」 → 「학습 자료실 접속 요청」·「개발 저장소 접속 요청」, 「보안 기록」 → 「event-01 상세」를 눌렀습니다. 이것은 **제공 예제 엔진의 요청**이며 실제 업무 앱·보안 집행이 아닙니다. AI 설명 요청·AI 점검·조치 버튼은 누르지 않았습니다.

종료 시 재현 브라우저를 닫고, 실행 경로를 확인한 PID 28488만 종료했습니다. 5192의 LISTEN 수는 0이고 복제본 `git status --short` 출력은 비어 있었습니다. 복제 폴더는 삭제하지 않았습니다.

## 코드 일치와 최종 커밋 갱신 규칙

복제본과 원래 작업 폴더의 on-client 추적 실행 파일 54개를 비교해 일치했습니다. 이 비교는 Markdown과 on-client/docs를 제외한 추적 파일을 경로순으로 정렬하고, CRLF를 LF로 정규화한 각 파일의 SHA-256을 `경로 공백 해시` 행으로 만든 뒤 마지막 개행을 붙여 집계했습니다.

집계 SHA-256: `6b974739e572b151f2400542ece8bdb9a7835d4658a4be3711ac526e517e1f61`

파일 일치는 실제 운영 연결을 증명하지 않습니다. 문서만 추가해도 Git 커밋은 달라지므로 위 측정 커밋을 새 커밋 번호로 덮어쓰지 않습니다. 수정이 있으면 새 커밋·실행 경로·환경·절차·관측·미확인을 별도 행으로 기록하고, 제출 직전에 **제출할 40자리 커밋 자체**를 새 폴더에서 확인합니다. 아직 만들지 않은 최종 커밋의 전체 재현 성공을 선언하지 않습니다.

## 학생 데이터 보존·백업·복원

| 대상 | 보존·백업 | 복원과 제한 |
| --- | --- | --- |
| 학생 코드·문서·Git 기록 | 원래 폴더와 미커밋 변경 보존. 승인한 파일만 커밋·원격 보관 | 특정 커밋을 별도 폴더로 clone해 비교. reset --hard·일괄 덮어쓰기 금지 |
| 실제 자료실 메모·학습 DB | 원래 DB와 운영 권한 유지. 허용된 개인 백업만 프로젝트 밖에 보관 | 기존 본인 한 건 복원 API·승인 절차 및 해시 검증 필요. 이번 재현에서 DB 읽기·변경·복원 미실행 |

Git clone은 학습 DB·개인 비밀·미커밋 작업의 백업이 아닙니다. 실제 데이터의 복구 권한·암호화·보존 정책은 기존 시스템 규칙을 유지하며 이 문서 작성으로 검증됐다고 하지 않습니다. 이번 재현은 새 서버 포트만 사용했고 원래 DB·인증 파일을 읽거나 옮기지 않았습니다.

- 2026-11-04 사용자가 21·22단계 공식 통과를 확인했습니다. 포털 직접 조회나 판정 대상 커밋 대조는 하지 않았으며 실제 운영 인증과 구분합니다. 최초 문서 작성 때의 미확인 상태에서 갱신한 기록입니다.
- 22단계 AI 원문 통과는 수료의 문서 검토 기준이며 운영 인증·v1.0 자동 인증·서버가 재현 명령을 실행했다는 증거가 아닙니다.
